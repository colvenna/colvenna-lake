# 验收契约

本文把 Issue #2 至 #5 的设计决定写成可执行的后续验收口径。数值是 **1.0 设计目标**，没有经过 M1 实测；客户端或引擎未验证的能力不得作为已交付能力销售。版本前提另见 [M0 跨组件能力矩阵](../research/version-capability.md)。

## 1. 身份、授权和绕过路径

### 1.1 信任边界

- colvenna-catalog 认证调用它的**服务身份**，通过自有、单独版本化的管理面登记 grants，在 Paimon 2.0.0 已发布的元数据、提交和凭证路径执行。Paimon 2.0.0 没有上游 REST Management API；不能把 master 的列 grant 接口列为 M2 可用能力。数据库/表级拒绝及凭证范围需要在服务端和对象存储两侧生效。`LoadTable` 拒绝本身不阻止已有 S3 凭证读取。
- Doris 的终端用户先经 Doris 认证及授权。若 Doris 只用一个服务 token 调 colvenna-catalog，catalog 只知道 Doris 服务身份，**不知道实际查询用户**。终端用户的表/列/行权限只能由 Doris 执行；在逐用户身份传递得到验证前，不能称 catalog 为终端用户的列级硬边界。
- 表前缀 STS 凭证限制可读写的**对象路径和有效期**，不限制该对象中的列或行。单表中混合权限的数据必须由可信查询引擎强制过滤，或拆到不同物理表/前缀。引擎服务身份可接触原始文件，因此其管理员与运行环境均属于可信计算边界。
- 所有读端都必须列入准入清单。拥有 S3 读权限的主体可以绕开 catalog、Doris 与行列策略；仓库桶拒绝一般用户直连，紧急访问账号单独授权、记录和复核。JDBC PoC 没有服务端授权，只能用于受信任、单租户验证环境。

| 访问路径 | 传入身份与授权点 | 存储凭证与可绕过处 | 可承诺范围 / 放行关口 |
| --- | --- | --- | --- |
| Flink CDC、分层、维护作业 | 每个作业独立 K8s 服务账号和 catalog token；catalog 校验目标库表及写/维护动作 | M2 按表签发短期凭证；若 Pod 有宽 S3 角色，可绕过 catalog | M1 JDBC 用域/表前缀 IRSA 隔离可信作业；M2 验证无宽角色且拒绝跨表 |
| Spark 批/回刷 | 每个批作业独立服务身份；同 Flink，并单独限制 `OVERWRITE`、删除等高风险动作 | 持有源表与目标表凭证的作业可读取这些表的完整行列 | M2 测试读、写、重放的正反授权；不把批作业 token 复用于交互查询 |
| Doris 外表 | 用户经 Doris 认证；Doris RBAC/经验证的策略执行终端用户权限；catalog 认证 Doris 服务身份 | Doris BE 拿到的表凭证允许读取表文件；管理员、外部表旁路及宽 S3 角色可绕过用户策略 | 默认先承诺隔离的表级读；敏感列/行仅在目标 Doris 版本、外部 Paimon 表和所有查询路径实测拒绝后开放 |
| 直接 S3/兼容对象存储 | IAM、桶策略和路径/操作约束；不经过 catalog | 已获授权的对象读取者能解析完整文件 | 普通用户默认拒绝；紧急账号属受控例外且不计入行列隔离承诺 |
| Iceberg 发布及外部读端 | 发布服务身份和 Iceberg catalog/读引擎各自授权；不继承 Paimon grants | Iceberg 元数据和数据文件 URL/凭证构成替代入口 | 敏感表默认不发布；只有目标读端的用户、表/列/行拒绝与撤销均实测后才能放行 |
| 用户已有的 Trino 或其他引擎 | 引擎独立认证和策略；catalog 只看到该引擎的服务身份，除非证明逐用户委托 | 引擎拥有 S3 凭证或缓存时可旁路 | 默认不接敏感表；需按该引擎重新验收所有入口 |

M2 的凭证签发还须证明：显式开启 `data-token.enabled` 后确实调用 `/token`，有效期有上限、表前缀外 `GetObject`/`ListBucket`/`PutObject` 被拒、已撤销服务身份不能续签、凭证泄漏的最大有效窗口可控；共享引擎不得向终端用户暴露其缓存数据凭证或让用户绕过 SQL 策略。若 Doris REST bearer/凭证下发不兼容，只允许在隔离的非敏感验证环境使用 JDBC/filesystem 读路径，不降级治理承诺。

**拒绝验收场景。** 用两个服务身份和两个 Doris 用户、两张不同前缀的表（其中一张有受限列/行）重复以下操作，并保存 HTTP/SQL 结果及 S3 数据事件。判定口径：“拒绝”必须是显式失败，即 colvenna-catalog 未认证返回 HTTP 401、无权限返回 403，S3 返回 `AccessDenied`，Doris 返回权限错误；超时、连接失败或空结果都不算拒绝通过。行级场景不要求报错，以按策略预先算出的期望结果集为准：受限行一条都不出现、允许的行一条不缺，才算通过；空结果只有在期望集合也为空时才通过。

1. 未授权服务身份调用 list/load/commit/token 与过期 token 续签均拒绝；即使已知对象 key，用其 STS 凭证读另一表也拒绝。
2. 仅有普通列权限的用户尝试 `SELECT restricted_col`、`SELECT *`、系统表/视图、物化视图、CTAS/导出与 JDBC 等价入口；再在已授权表加入未复核敏感列，复测实际用户角色、宽授权、历史快照和缓存。任一入口能返回受限值，则列级能力未通过，不对该用户开放原始表。
3. 行限制用户以谓词、聚合、join、time travel、缓存结果和 Iceberg 替代入口读取受限行。任一入口泄漏则行级能力未通过，改用独立脱敏表或关闭该入口。
4. 无直接对象权限的用户用 S3 API 读已知 key 应被 IAM 拒绝；获批紧急角色的访问应出现审计记录。每个准入读端都要独立重复 2、3，不从 Doris 的结果推定其他引擎安全。
5. `mysql_sync_database --mode combined` 捕获新源表及既有表新增 `id_card_no` 时，核对新表只在隔离区、新列在所有已授权读端不可见；`$schemas` 发现、Owner 审批、登记簿版本和发布/拒绝结果须能串联。若列白名单在目标 Doris 外部表上未通过，验收阻断可读表自动加列或验证独立物理表发布路径。
6. 未认证访问：以 [HLD 12.1 暴露面清单](hld-realtime-lakehouse.md#121-边界与威胁模型)为唯一的入口来源，从集群外、不带任何凭证，逐一访问清单中的每个入口。每一项都必须返回 401/403 或认证失败，或者连接被拒、超时（即没有暴露）。另外专门检查三项：没有 `pods/portforward` 权限的 IAM 主体，不能对 Flink、Spark 或监控 Pod 建立 port-forward；Doris root/admin 用空密码登录必须失败；Doris FE 的 HTTP 端口从集群外不可达。任何一项能匿名读到数据或元数据，该环境就不得进入后续验收。

### 1.2 敏感数据识别、策略生命周期与审计

新源表、新列、分层宽表、临时表、测试副本和受管导出都要登记 Owner、L1–L4 级别、敏感类别、数据主体键映射、来源/下游与保留责任；[HLD 12.5](hld-realtime-lakehouse.md#125-schema-与元数据一致性) 是级别对应访问、去标识化和审计默认控制的准入来源。个人数据最低 L3，敏感个人数据与可还原个人轨迹等组合结果按 L4 审查；类别另触发删除及 DV 约束。字段名与正则只能产生**候选**列标签，需 Owner 复核。`LakeTable.upstream` 须与按 Flink 语义解析并绑定到 catalog 的实际输入表核对，下游级别不得低于最高实际输入级别；无法证明完整来源或声明不一致时拒绝发布。降级须有去标识化证据和审批，组合敏感可上调。未分类、未复核或血缘不明的数据按临时 L4 控制隔离，不向一般用户、Iceberg 或直接 S3 入口开放。

1.0 的平台登记簿保存带 schema 版本的机器可读表/列级别、类别和复核状态，受控 table option 只镜像表级摘要，column comment 只供展示，不是准入判定或权限执行点。`combined` 新表先进入隔离区；`$schemas` 新版本触发候选识别和复核，**不能代替事前的读端拒绝**。即使原表是 L1/L2，自动新列也须在所有用户读端默认不可见；Doris 列白名单能否做到这一点须在目标 Paimon 外表上逐入口验证，失败则暂停可读表自动加列或发布独立物理表。Doris MV/内表、缓存和受管导出与删除共用跨系统副本登记簿并继承级别。上游 entity label 只见于开发分支，正式发布和联调前不作为强制策略来源。

服务身份和临时授权申请至少绑定主体、资源、允许动作、用途、环境、审批责任人和失效时间；角色变化、用途结束、到期或数据分类上调时撤销并验证缓存/短期凭证不会续签。Doris 终端用户 grant 的声明式到期回收列为阶段 2 候选，不假定 Doris 原生支持。动态脱敏可以按角色、用途和场景设计不同输出，但在 Doris 外部 Paimon 表、视图、聚合、导出及所有替代入口验证前，不能声称同一原始表可对不同用户安全地返回不同明文形态。可交付的回退形态是独立物理表/前缀中的去标识化数据，且同样须做旁路拒绝。手机号等低熵标识符如需稳定 join，必须使用 KMS 保护密钥的 keyed HMAC 或受控 token；密钥轮换可能破坏跨版本 join，LLD 须定义版本与重算流程。

审计最小事件为：目录与 grant 的允许/拒绝、提交、凭证签发、查询、受管导出和紧急对象访问；每条关联请求/查询 ID、实际终端用户与服务身份（若两者不同）、资源、动作、结果、时间、审批单和策略版本。阶段 2 可把**已可靠识别的查询表**与查询时刻生效的分级登记簿关联，得到表级访问报告和扫描量/非工作时间候选告警；不能用 Doris 常规 SQL audit log 推断实际命中的列或“掩码已执行”，截断 SQL 与无法识别的表保持未知。若启用脱敏，确切命中字段/策略及是否返回明文须有经验证的额外引擎事件，否则标 `NOT_VERIFIED`。导出记录目的地、数据集和条数；SQL 字面量、参数及审计载荷不得无意复制 PII。

补充拒绝场景：新增敏感列未复核时查询与导出被阻断；临时服务授权到期后旧 token 不再续签、相关操作被拒；Doris 查询审计与 colvenna-catalog 服务 token 的身份缺口被明确记录，不把服务身份冒充终端用户；未批准用途的外部发布/测试环境同步被拒；策略服务或标签缺失时不会退化为允许。保存拒绝结果与审计事件，避免只保存配置快照。

## 2. 延迟、正确性和故障目标

### 2.1 测量协议

同一条合成 CDC 事务/事件携带唯一 ID、源端事务提交时间或 Kafka broker 持久化时间、源 offset、业务版本与校验值。观测端记录首次在 ODS、DWD、DWS 的**已提交 Paimon 快照**中读到正确版本的时间，Doris 外表首次查到的时间，以及看板经物化视图首次查到的时间。统一时钟并记录时钟偏差；超出容许偏差的样本无效，不用 Flink 收到记录的时间冒充源端起点。删除以目标键首次**查不到且聚合正确撤减**为终点，旧版本/旧行被读到算错误。

M1 基线负载档为一张 CDC 表持续 1,000 变更/秒、一张 Kafka 事件表持续 10,000 条/秒、单记录不超过 2 KiB、连续 24 小时；查询档为千万行表、7 天窗口、10 QPS 固定看板查询与 1 QPS 交互查询。每条路径至少 10,000 个有效样本，分别按 insert/update/delete 和事件流统计 p95、p99；样本不足只报告观察值，不判定通过。基线档是拟验收环境而非产品容量上限。

**稳态**指源端持续负载、无故障至少 30 分钟且源端积压不再增长；**积压期**指注入 10 分钟上游暂停或写入故障后到追平之前；**恢复期**从故障注入开始到作业、catalog 和查询结果追平。以下延迟目标仅用于稳态；积压期记录最大滞后和清空时间，不能把积压样本混进稳态分位数。积压期目标：10 分钟暂停解除后 ≤30 分钟内，各路径滞后回落到稳态 p95 目标以内（即追赶吞吐至少约为稳态负载的 1.33 倍）；未达到时报告实际清空时间和追赶吞吐，不判定通过。

| 路径 | 起点 → 终点 | 稳态 p95 / p99 目标 | 设计预算或前提 |
| --- | --- | --- | --- |
| 源库或 Kafka → ODS | 源提交/持久化 → ODS 快照可读 | ≤2 / 5 分钟 | CDC 捕获、checkpoint 等待、提交；事件流单独统计 |
| ODS → DWD | ODS 快照可读 → DWD 正确版本快照可读 | ≤2 / 5 分钟 | 流读、计算、下游 checkpoint 和提交 |
| DWD → DWS | DWD 快照可读 → DWS 正确聚合快照可读 | ≤2 / 5 分钟 | 包括撤回或删除对聚合的影响 |
| Paimon → Doris 外表 | 目标快照提交 → 新查询首次读到该版本 | ≤3 / 6 分钟 | 元数据缓存刷新、DV 未合并数据可见性和查询轮询；M1 必须逐一确认 |
| Paimon → Doris 物化视图 | 目标快照提交 → 刷新后的看板首次读到正确聚合 | ≤5 / 10 分钟 | 刷新排队、执行、发布及查询缓存；只适用已验收的查询模板 |
| 源库 → Doris ODS 外表 | 源事务提交 → Doris 查到正确版本 | ≤5 / 10 分钟 | 独立实测，不从两段 p95 相加推断 |
| 源库 → DWS 看板 | 源事务提交 → DWS 物化结果正确 | ≤15 / 30 分钟 | 独立实测全链路，包括每层与 MV |

“源库到 Doris 1 分钟内”暂不作 1.0 承诺：即便 30 秒 checkpoint，CDC 捕获、提交、独立 compaction、Doris 缓存和查询轮询仍占用时间。示例工程预算为源捕获 15 秒 + 首次 checkpoint 30 秒 + 提交 15 秒 + Doris 刷新/DV 维护 90 秒 + 查询观测 15 秒，合计 165 秒；还未覆盖长尾。若 M1 测出更快结果，可另设快速档，但不能以 checkpoint 间隔替代端到端测量。固定看板查询本身在上述负载下目标 p95 ≤3 秒、p99 ≤10 秒；任意 ad-hoc SQL 不作秒级承诺。

### 2.2 正确性、RPO/RTO 与注入

每条输入用源事务 ID/offset 加业务版本建立期望结果。已提交记录在最终主键状态或 append 唯一事件集合中缺失是数据丢失；同一事件 ID 多次出现在 append 结果是重复；CDC 的旧业务版本覆盖新版本是乱序错误；一次 commit 的文件存在但不可通过最新快照查询是可见性错误。多写者测试要比较源 ID 集合、每个 snapshot 的提交身份、文件引用和最终查询，**零快照丢失**不等于仅作业成功。未获业务版本的记录不能靠到达时间推断正确顺序，应阻断该源的“乱序正确”承诺。

RPO 目标为**已确认的 Paimon 提交零丢失**；未完成 checkpoint 的源记录须仍在源库 binlog/Kafka 保留窗内并可重放，否则报告实际 RPO，不声称零丢失。单个 Flink 作业/Pod 重启、写入方在提交前后崩溃的 RTO 目标 ≤30 分钟，从故障注入起算；catalog、元数据后端或对象存储（S3 503/短暂不可用）的注入故障 RTO 目标 ≤60 分钟，从故障解除起算，并单独记录故障持续时长。提交结果未知且能自动查证并幂等重试的，RTO 目标 ≤30 分钟，从返回超时或结果未知起算；需要人工处置的，单独报告处置时长，不计入自动恢复达标。各项 RTO 的终点均为积压清空且所有受影响查询结果正确，不能只按 Pod Ready 判定；同时报告从故障注入到恢复的完整时长。Doris 元数据缓存未刷新不单设 RTO，按 Paimon → Doris 外表的稳态新鲜度目标判定。源端保留窗必须大于“最大预期故障 + 最慢回放 + 安全余量”，M1 核实数值。

M1/M2 故障矩阵至少注入：checkpoint 失败后源重放、写入方在快照提交前/后崩溃、提交返回超时且结果未知、两写者冲突、S3 503/短暂不可用、JDBC 或 REST catalog/元数据后端短暂不可用、Doris 元数据缓存未刷新。`OUTCOME_UNKNOWN` 时先按提交 ID/快照和文件引用查证，再幂等重试或人工处置；不能盲目重做 overwrite。每次记录故障点、源位点、前后快照、重试次数、最终集合和恢复时长。没有覆盖这些注入，正确性和 RTO 均未通过。

## 3. 历史更正与分层回刷

“最终一致”指在显式更正范围、输入版本和下游依赖图确定后，ODS、DWD、DWS、Doris 外表及派生结果收敛到同一业务事实。各表独立提交，**不承诺跨表瞬时原子可见**；对外发布某一批次的完成信号前，不允许把新旧批次混成已完成结果。

| 更正类型 | 传播方式 | 必须做的额外动作 |
| --- | --- | --- |
| 主键 CDC update/delete，带有可比较的源业务版本，ODS `input` changelog 完整，下游支持撤回 | 正常流可传播 | 核对每层 consumer 位点、正确版本与 Doris 结果；不满足任何前提就进入显式回刷 |
| append 新事件或主键新 insert | 正常流追加 | 迟到事件跨窗口时重算受影响聚合；不能仅凭分区完成信号认定无迟到 |
| 历史 `INSERT OVERWRITE`、append 行级 UPDATE/DELETE、来源重放、聚合逻辑或 schema 更正 | **显式重算所有受影响下游** | 覆盖提交默认被流读忽略；`streaming-read-append-overwrite=true` 只追加覆盖后的新行，不撤回旧行，不能作为正确性修复 |

每个更正批次登记：业务键/时间范围、受影响分区与下游依赖、源版本或 offset 边界、输入/输出快照 ID、查询模板、负责人及完成状态。按依赖顺序重建受影响 DWD/DWS 分区或键集合，刷新/重建 Doris MV 和内表；外部 Iceberg 发布若开启，也必须验证其可见版本。只看批作业 `FINISHED`、`_SUCCESS` 或 snapshot ID 增长不足以放行。完成证据至少包括受影响键集合、记录数与校验聚合、删除键的负向查询、每层所读上游版本和 Doris 派生结果；不一致时标记 `NEEDS_RECONCILIATION`，对外显示旧批次或“结果待更正”。

同一分区有常驻流写时，不能仅依赖 Paimon strict mode 的冲突拒绝。无论回刷由何种引擎或编排执行，安全边界都是：覆盖前该分区的流写已在 checkpoint/savepoint 边界**暂停或隔离**，并记录可重放的源位点；覆盖和下游重算完成后，才从边界后的位点继续消费，并核对去重结果。无法安全暂停/重放的活跃分区不得原地 overwrite，应写入隔离的新版本再切换读端。append 事件没有稳定 event ID 时重放不能证明无重复，必须补 ID 或整分区重建。

后续验收至少包含：旧订单金额更正后 DWS 聚合撤减并重加；历史订单删除后所有层和 MV 均无该订单贡献；同一输入位点重放及同一更正批次重复执行，最终集合与聚合不变；流写与回刷并发时被围栏拒绝或序列化；遗漏下游或 MV 刷新失败时不能发完成信号。

## 4. 合规删除的副本范围与完成证据

`colvenna forget` 只能对**已登记且可控制的副本集合**给出完成结论。删除请求首先枚举主体键映射、每层依赖和可能包含数据的文件/分区；无法定位全部受管副本、存在无界 tag/branch/consumer/备份保留或法律保留时，登记 `BLOCKED_POLICY` 并给出责任人和预计复核时间，不能返回“成功”。源业务数据库、用户自建 Kafka、用户自接的 Doris/Trino、第三方 Iceberg 读端导出和其备份由各系统拥有者负责；平台给出通知和回执接口，不替外部系统出具完成证明。

| 副本/入口 | 平台责任 | 必要清理或隔离证据 |
| --- | --- | --- |
| ODS、DWD、DWS 当前 Paimon 表 | 执行删除及受影响聚合重算 | 正向记录数/聚合核对和目标键负向查询，绑定新快照 ID |
| 历史 snapshot、tag、branch、consumer 位点、`input`/`lookup` changelog 文件、DV 旧文件、orphan | 停止新增受影响引用，界定并解除保留，重写仍含主体的文件，执行过期与清理 | 遍历引用图、tag/branch/consumer 清单、S3 对象及版本清单；旧快照可读期间不得声称全域不可查 |
| Flink checkpoint/savepoint 与作业本地缓存 | 清理可重放旧主体的状态或在恢复时强制应用删除墓碑 | 状态保留/删除记录和恢复演练；恢复旧状态不得重新引入主体 |
| 平台托管的 Doris MV、Unique Key 内表、缓存及其备份 | 刷新/删除派生行，失效缓存并清理恢复副本 | 指定查询模板负向查询、刷新/备份清理记录 |
| 平台托管 Iceberg 元数据、开放端缓存与临时凭证 | 撤销可访问旧版本的入口并推进发布 | 读端版本、凭证撤销和负向查询；未验证的外部读端不得纳入完成声明 |
| 平台托管临时表、测试副本、导出文件 | 与原表同等登记、删除和备份核验；禁止无归属的持久副本 | 逐份目的地清单、负责人回执、删除或去标识化证据 |
| 平台托管 S3 主桶、复制桶、备份、对象版本和 Doris Storage Vault | 按副本逐一执行删除并等待所有恢复窗口结束 | 带对象版本的清单、清理任务结果和备份目录/恢复入口核对；CloudTrail 只作辅助审计 |
| 审计日志与导出 | 从设计上禁止记录原始 PII；若已有原值，视为额外副本。Doris `__internal_schema.audit_log` 默认保留 30 天，且会记录 SQL 字面量 | 字段核查与单独清理/保留决定；不可遗漏 |

**1.0 拟准入策略。** 对可删除的 PII 表，主表 snapshot 时间保留上限 24 小时，同时配置快照数量下限与主动过期作业，使旧快照不会因低写入量永久被 `snapshot.num-retained.min` 钉住；若用 `changelog.time-retained`、`changelog.num-retained.*` 单独设置 changelog 保留，不得超过上述 snapshot 上限；不创建覆盖 PII 的长期 tag/branch，consumer 最长滞后 24 小时并须可安全移除；受管 checkpoint/savepoint 不得在恢复时绕过删除墓碑，保留的 checkpoint 与 savepoint 同备份一样最长 7 天；主桶关闭版本控制和复制，若有托管备份，所有备份副本最长保留 7 天、无 Object Lock/法律保留。Doris 审计日志是平台级副本：其保留期须经 `dynamic_partition.start` 压到 7 天以内，或证明可按主体定点清理；两者都做不到，就不对外提供 9 天物理删除目标。任何新增副本都须登记保留上限，超出上限的表不能进入有时限删除服务。以上是产品准入条件，不是 Paimon 或 AWS 自动保证的值。

对通过准入的请求，设计目标为 `t0 + 24 小时`内达到**受管读入口逻辑不可查**，`t0 + 9 天`内达到**受管存储及备份物理不可恢复**；`t0` 为清单、保留上限与所有者确认后的正式受理时间。请求到 `t0` 的受理时长单独计量，对外报告时与 24 小时/9 天一并给出；受理上限由 LLD 结合适用法规的答复时限设定，超限同样进入 `SLA_BREACH`。24 小时目标要求先围栏 time travel/tag/branch、历史外部入口与缓存，再核对当前表和 Doris 派生结果。9 天目标的最坏预算是：受影响旧状态的新增备份在 `t0 + 24 小时`前被围栏，最后一份旧备份最多保留 7 天，再用最多 24 小时清理并核验；主桶的重写、快照过期及孤儿清理在这段备份窗口内完成。若任何备份可能在围栏之后重新携带旧主体，或主桶不能在窗口内清完，就不能准入该目标。**这只是受限配置下的设计上限，M1/M3 必须实测并校验每个副本的实际清理时长后才能对外承诺**。`max(snapshot, tag, consumer) + compaction` 既遗漏独立备份，也不能证明 S3 实际删除时刻，不能用作 SLA。

逻辑完成须对每个受管 SQL/REST/开放读入口、当前查询和允许的历史查询执行负向查询，查询缓存失效，并证明恢复旧 checkpoint 不会重现。物理完成须遍历所有登记副本的活动版本及非当前对象版本、Paimon 引用、Doris 副本和备份恢复目录，取得无可恢复副本的清单/任务回执；S3 `HEAD 404`、CloudTrail 删除事件或 SQL 查不到任何一个单独都不够。无法验证的副本保持 `PENDING_EVIDENCE`，逾期进入 `SLA_BREACH` 并隔离入口、告警、人工接管及告知责任方；法律保留进入 `BLOCKED_HOLD`，不能伪装成已物理删除。对外只报告已经证明的范围和完成级别。
